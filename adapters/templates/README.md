## decision-form.html — 복잡한 의사결정 요청 폼

사용자에게 한 번에 여러 결정을 받아야 하거나, 각 결정에 시나리오·영향·옵션 비교가 상세히 필요한 경우 사용한다. 채팅 내 라디오 위젯·평문 옵션 나열보다 비동기 검토·일괄 회신에 유리하다.

### 트리거 (모두 해당하면 우선 사용)

- 결정 사항이 3개 이상
- 각 결정에 시나리오·코드·매트릭스 등 부가 설명이 필요
- 옵션 간 트레이드오프가 명확하여 사용자가 시간을 두고 비교해야 유리
- 결정 결과를 다음 사이클(디벨로퍼 재작업 지시, 명세 갱신 등)에 그대로 전달해야 함

### 산출물

- 경로: 프로젝트 루트의 `docs/` (없으면 생성)
- 파일명: `<주제>_<목적>.html` (예: `plan_full_mirror_v2.html`, `review1_fix_decisions.html`)
- 반복 사이클은 `v1`, `v2` 등으로 버전을 명시하여 결정 히스토리 보존
- 결정 완료 후에도 HTML은 삭제하지 않는다 (사용자 요청 시에만)

### 필수 구성

1. 헤더 (제목·부제)
2. 목차 (앵커 이동)
3. 종합 요약 표 (항목 한눈에)
4. 항목별 패널 — 위치 / 시나리오 / 영향 / 옵션 라디오 (추천안에 「추천」 뱃지) / 메모
5. 추가 메모 (전체)
6. 하단 고정 툴바 — 「결정사항 모으기」·복사·추천안 모두 선택·초기화

### 결정사항 출력 형식 (필수)

「결정사항 모으기」 결과는 사용자가 그대로 채팅에 붙여넣을 수 있는 Markdown.

```markdown
# <문서 제목>

생성: <로컬 타임스탬프>

## <Q-ID>. <옵션 그룹 제목>
- 선택: **<선택지 전체 텍스트>**
- 메모: <자유 텍스트>  (입력된 경우에만 출력)

## 추가 메모  (입력된 경우에만 출력)
<전체 자유 메모>
```

### 사용 흐름

1. 트리거 조건 점검
2. `decision-form.html`을 `docs/<주제>.html`로 복사
3. `<header>`·요약 표·항목별 패널의 더미 콘텐츠를 실제 결정 사항으로 교체
4. 옵션 라디오에 `data-question`(Q-ID), `data-title`(옵션 그룹 제목) 채움
5. 추천 옵션 input에 `data-rec="true"` 추가 ("추천안으로 모두 선택" 버튼이 자동 인식)
6. 사용자에게 `file:///...` 경로 안내 → 회신받은 Markdown 결정 텍스트를 다음 사이클에 전달
